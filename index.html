Good Life OS

A private personal health dashboard, run locally by one person for their own use.

What this is

Good Life OS is a personal health dashboard that runs on its operator's own computer. It brings weight, nutrition and short daily check-ins into one place, so its operator can see their own trends over time. An optional connection to the operator's own Oura account is in development.

It has exactly one user, who is also the person who built and runs it. It is not a product, not a service, and not offered to anyone else. There are no accounts to create, nothing to sign up for, and no way for another person to use it.

This site is the only public part of Good Life OS. These three pages exist because the Oura API requires an application to publish a privacy policy and terms. The dashboard itself, its database and every record in it stay on the operator's computer and are never published.

What it does today

  • Records manually entered weigh-ins, keeping every reading and letting the operator choose which one represents each day.
  • Records a daily check-in — energy, mood, hunger and stress ratings, water, optional bloating and pain ratings, and a short note — as one row per day.
  • Records daily nutrition totals, with a mark for how complete each day is.
  • Shows those figures as trends over 7, 30 and 90 days, with the source and date of every number visible, and gaps left as gaps.
  • Imports and exports nutrition and weight records as CSV files on the operator's own computer, with a preview before anything is written.
  • Exports check-ins as CSV. Check-ins are export only — there is no check-in import, and the application says so where the export is offered.
  • Makes local backup snapshots of its database, and can verify and restore them.

What is not built yet

Listed here so this page does not describe features as though they exist:

  • The Oura connection — in development. Nothing has been synced from Oura at the time of writing. The privacy policy describes how Oura data will be handled once the connection is enabled.
  • MyFitnessPal CSV import — in development.
  • Tape measurements, gut observations and care routines — planned.
  • Correlation and pattern analysis — planned.

What it deliberately does not do

  • It does not produce a composite wellness score, a weight-loss promise, a prescribed calorie target, or any treatment recommendation.
  • It does not diagnose anything, and it is not medical advice.
  • It does not infer body composition from weight and tape measurements.
  • It does not upload health records anywhere. There is no hosted dashboard, no account server and no remote copy of the database.

How it runs, accurately stated

Good Life OS is a web application that runs a web server on the operator's own computer, which the operator opens in their browser. That server is bound to the loopback interface, so it is reachable only from that computer and not from any network. During Oura authorisation it also runs a second, short-lived local listener to receive the authorisation response, which shuts down as soon as the exchange completes.

The application does send network requests, and it is worth being precise about which. Once the Oura connection is enabled, it will send authentication requests and data requests to Oura's API over an encrypted connection. Those requests carry the operator's own access credentials and the date ranges being requested. No other destination is contacted: there is no analytics service, no telemetry, no crash reporting and no third-party component.

Health records themselves are never uploaded. They are written to a database file on the operator's computer and stay there.
